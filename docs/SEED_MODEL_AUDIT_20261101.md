# 金種三層モデル 監査・実装記録

監査日：2026-11-01。モデル：`seed-v1`。対象CURRENT：`2026-11-01-r37`。

## 1. 判定と採用範囲

**三層を分離する構造を採用する。初期Tierは暫定の定性評価として採用し、具体的な使用承認や定量ROIとは分ける。**

| 層 | 評価するもの | 初期実装で意味しないもの |
|---|---|---|
| 種族の投資候補Tier | 良個体を長期採用する前提での候補優先度 | 全種族の等条件ROI順位、公式Tier、今すぐ使う指示 |
| 手持ち個体の投資候補Tier | 個体と役割を限定した候補優先度 | 種族Tier・一般個体品質・PRの単純転記 |
| 具体的な投入案 | 対象、時点、目標SLv、必要数、前提、在庫、明示判断 | 必要数が計算できるだけで成立する使用承認 |

評価状態 `validated / provisional / unassessed / stale` と、適用条件 `broad / conditional / not_applicable / unknown` を分離した。未知を0、低Tier、使用不可と同一視しない。旧 `main_seed_cap`、旧シナリオ、既存Tierから新しい使用推奨を自動生成しない。

採用プロファイル `seed-qualitative-v1` は「良個体を長期使用する場合の定性的な候補優先度」である。種族・個体間の数値的な投資効率を測定した結果ではない。

## 2. 初期評価の内容と限界

### 種族候補

初期収録は8種族で、すべて `provisional / conditional`。全種族の網羅的なTier表ではない。

| 暫定Tier | 種族 |
|---|---|
| S | サーナイト、デンリュウ、エーフィ |
| A | プクリン、パーモット、ドダイトス、ジバコイル、デデンネ |

成立条件、理由、比較プロファイル、評価日、効果表版、出典を `M_SeedTier` に保持する。回復不足がない、編成しない、交代予定が近い、食材供給が不足する等の場合は、この種族候補順位だけで投入を決めない。

### 手持ち個体

| 個体 | 初期評価 | 投入判断 |
|---|---|---|
| IND-0002 プクリン | 暫定A・条件付き | 未確定。使用承認なし |
| IND-0010 デンリュウ | 暫定A・条件付き | 未確定。使用承認なし |
| その他の現役33体 | 未評価 | 低評価や使用不可を意味しない |

35現役個体を対象とし、8退役個体は候補に含めない。現在種と将来種を区別し、将来種のTierを現在種の評価として扱わない。

金種在庫の原記録は **2026-09-28時点の「約8個」**。`reportedValue:8 / certainty:approx / value:null` として保持し、現在の確定在庫として使わない。r37への版更新は、ゲーム内の最新状態を再計測・再同期したことを意味しない。

### 計算できる範囲

- 現在SLvと明示された目標SLvから、対応スキルの参考必要数を計算する。
- げんきオールS、エナジーチャージM、料理パワーアップS、料理チャンスSの、1回発動あたりの効果差を固有の単位で示す。
- 現在SLvに含まれる進化・解放済み補正を二重加算しない。今使う案から未実行の進化や将来サブスキルを先引きしない。
- 将来案は前提・実施順・投入時点を明示した場合に限り、現在案と別に扱う。

特殊・複合・未対応スキルを既存の基礎スキルへ代用しない。発動回数、編成時間、実効回復、料理・食材・鍋の条件が不足するため、日次増分エナジー、金種1個あたりのROI、投資回収期間は未算出である。PRを絶対発動回数へ変換しない。

効果表の数値出典は主にコミュニティ資料。公式更新告知で裏付けられる事項と、全レベルの実数表の出典を区別し、`seed-rules.js` に記録した。`seed-effects-2026-11-01-v1` は収録効果表の版であり、公式ゲームアプリの版番号ではない。

データ契約の詳細は [SEED_MODEL_DATA_CONTRACT.md](SEED_MODEL_DATA_CONTRACT.md) を参照。

## 5. 生成器の再現性と既存データ

元の公開生成器には、r36以降を無制限に受け入れながらr36用メタデータを出す問題と、再生成時に公開データの一部を再現できない問題があった。今回必要な範囲で次を修正した。

- `2026-10-25-r36` と `2026-11-01-r37` の契約を明示し、未知のrevisionは停止する。r36の旧メタデータは保持する。
- `P_Individuals.current_species_key` を公開の `currentSpeciesKey` に出力する。
- 料理・投資情報を付けた最終 `roles` から `coverage` を再構築し、表示用コピーが古いまま残る問題を解消する。
- 旧 `main_seed_cap` の公開文字列形式を維持する。種モデルの必要数や使用推奨には使わない。
- manifestからrevision、schema/app/model版、効果表版、判断日を照合し、既存の厳密な件数・測定履歴検査を維持する。

修正後のr36再生成と元公開data.jsの意味上の差は、以下の原記録復元3件だけだった。
